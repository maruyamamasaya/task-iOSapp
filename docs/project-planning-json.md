# プロジェクト計画JSONの形式案

WBSとガントは別のデータにせず、同じ工程一覧を使って表示を切り替える。1プロジェクトにつき1ファイルとし、既存プロジェクトのUUIDで対応付ける。

現時点では形式案のみ。画面はプロジェクト選択から開くプレビューで、JSONの読込み・保存・同期は未実装。アプリからの工程追加も提供しない。既存のTaskItem、SwiftData、Dotタスク正本のschemaは変更しない。

## 例

UUIDは説明用。利用時はprojectIdに既存プロジェクトのUUIDを使い、工程IDは初回に生成して以後固定する。

```json
{
  "schemaVersion": 1,
  "projectId": "11111111-1111-4111-8111-111111111111",
  "revision": 1,
  "updatedAt": "2026-10-23T13:00:00+09:00",
  "timeZone": "Asia/Tokyo",
  "items": [
    {
      "id": "22222222-2222-4222-8222-222222222222",
      "parentId": null,
      "title": "準備",
      "sortOrder": 0,
      "startDate": "2026-10-26",
      "endDate": "2026-10-28",
      "progress": 0
    },
    {
      "id": "33333333-3333-4333-8333-333333333333",
      "parentId": "22222222-2222-4222-8222-222222222222",
      "title": "必要な資料をそろえる",
      "sortOrder": 0,
      "startDate": "2026-10-26",
      "endDate": "2026-10-27",
      "progress": 0
    }
  ]
}
```

## 項目の扱い

- `schemaVersion`は形式の版、`revision`はプロジェクト単位の更新番号。将来の更新は直前revisionとの一致を条件とし、競合を上書きしない。`updatedAt`はタイムゾーン付き日時。
- `projectId`は既存のProjectのUUIDを参照する。名前はプロジェクト一覧から取得し、JSONのタイトルから新規プロジェクトを自動生成しない。
- `items[].id`は工程の安定UUID。`parentId`は同じファイル内の親工程ID、最上位はnull。孤立した親参照、自己参照、循環は受け付けない。
- `sortOrder`は同じ親の中での表示順を表す0以上の整数。同順位は配列順とする。WBS番号（1、1.1など）は親子関係と表示順から計算し、保存しない。
- `startDate`と`endDate`はYYYY-MM-DD、終了日を含む期間。未定は両方null、設定する場合は開始日≦終了日。未定の工程もWBSには表示し、ガントでは期間未設定として扱う。予定日を固定期限へ流用しない。
- `progress`は0〜100の数値。現行プレビューの0〜1とは読込み時に換算する。工程の進捗から既存タスクの完了状態を変更しない。親工程の自動集計は別途設計する。

## 保存・連携の境界

将来は専用の`project-plans/<projectId>.json`等へ保存し、WBSとガントが同じRepository／Storeを参照する。保存時は参照・日付・進捗を検証し、atomic保存と読戻し照合を行う。既存の`tasks.json`へこの形式を混ぜず、`canonical_tasks.py`で扱える実装があるとも見なさない。新しい保存先と正規更新経路の導入は未実施。

画面と工程JSONの紐付けが入るまでは、プロジェクトを選んでも工程の空状態を表示する。サンプル工程や架空の進捗を自動挿入しない。
