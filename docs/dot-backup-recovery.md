# Dotデータのバックアップと復旧

2026-10-21 JST。既存のSwiftDataバックアップとは別の手順。正本、操作受信箱、iPhoneの送信待ちは役割が異なる。Widget共有ファイルは表示用の派生データであり、復旧の正本にしない。

## 保全対象

| 場所 | 対象 | 理由 |
| --- | --- | --- |
| Mac専用領域のstate | tasks.json | 全タスク、revision、適用済み操作receipt |
| 同じstate | bridge.sqlite | 受信操作、競合、適用済み確認応答、配信投影 |
| iPhoneアプリ領域 | DotLocalRelay/paired/<bridgeID>/state-v1.json | 端末UUID対応、キャッシュ、未送信outbox、適用履歴 |
| iPhoneアプリ領域（使用している場合） | DotTasks/local-v1.json | 従来JSON取込みとUUID対応 |

Mac専用領域は `~/Library/Application Support/CalendarTaskApp/DotLocalRelay`。上記タスクデータも私的な情報として扱い、非公開・所有者のみ読書き可能な場所へ保管する。auth、tls、pairing-inbox等の秘密をタスク用アーカイブへ混ぜない。接続設定の再作成とタスク復元を分ける。KeychainのThisDeviceOnly設定は端末交換での引継ぎを保証しない。

## 一貫したコピーの取り方

Mac稼働中の取得は、正規CLIと同じ `tasks.json.lock` の共有ロックを保持し、その間に正本JSONを読み、SQLiteのbackup APIで同じ時点のDBを別パスへコピーする。生のSQLiteファイルだけのコピーや、別時刻の正本とDBを組み合わせない。ロック取得不能時は待つか中断し、プロセスを強制終了しない。

コピー先は0700の専用ディレクトリ、ファイルは0600とし、日時、bridgeID、件数、正本SHA256を記録する。秘密や本文を検証ログに出さない。恒久バックアップの保管先・保存期間はまだ未設定で、今回の一時コピーは長期バックアップではない。

iPhoneは同期や操作の担当と調整し、上記stateファイルだけを正規のアプリコンテナ経路で取得する。同期中のMac/iPhoneのコピーを単一の同時点と扱わない。outboxがある場合も消したり、operation IDを変えたりせず保持する。

## まず隔離領域で確認する

1. 本番へ上書きせず、Mac正本とDBの組を一時領域へコピーする。
2. JSONが読めること、bridgeID、task ID、revision、重複、適用済みreceiptを検証する。
3. `CanonicalBridge(コピー先DB, bridgeID, コピー先JSON)` を開いてfeedを読み、正本と投影が一致することを確認する。feedは未適用操作を回復し得るため、必ずコピーに対して実行する。
4. 不一致・破損・不明な操作があれば、正本/DBを直接編集せず停止する。古い版への上書きで合わせない。

## 実際の復元が必要になった場合

稼働中継と他の書込み担当を止め、現在の正本・DB・iPhone outboxも先に保全する。隔離検証済みの同じ組を復元対象とし、現在より古いrevisionやreceiptの欠落がないか比較する。正本とDBの片方だけを安易に巻き戻さない。稼働用service、認証、TLS、署名、App Group、既存SwiftDataはデータ復元と分離する。

中継再開後は同じoperation IDによる再送・確認応答を確認する。iPhoneを再インストールしたり、outboxを空のキャッシュで置換したりしない。Mac交換・iPhone交換・実際の破損からの本番復元は未検証で、今回成功と扱わない。

## 今回の検証範囲

本チャットで共有ファイルロックとSQLite backup APIを使って50件・受信保留0件の組を一時領域へコピーし、CanonicalBridgeから読取り成功。50件の全属性が一致し、適用済みreceipt1件が正本内receiptと一致、コピーした正本のバイト列も不変だった。実データの保存場所は今回専用の一時領域で、検証ログに本文や資格情報は含めていない。

本番のファイル置換、プロセス停止・再起動、実機操作、テスト端末作成は行っていない。iPhone outboxの実復元、保留操作を含むバックアップからの本番復元、長期バックアップの自動化・恒久保管は未確認/未実装。文書と隔離コピー検証のみで、アプリコードは変更していない。
