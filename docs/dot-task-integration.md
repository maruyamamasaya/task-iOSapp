# Dot連携の現在仕様と確認範囲

更新: 2026-10-22。実装を正とし、現在の運用・入力契約・検証範囲の入口をこの文書へ集約する。個人のタスク内容、端末識別子、操作ID、復元資料は公開リポジトリへ含めない。詳細な実機検証記録はローカルで保持する。

## 保存と同期

- 正本はMacの `~/Library/Application Support/CalendarTaskApp/DotLocalRelay/state/tasks.json`。操作は正規CLI `Integrations/DotLocalBridge/canonical_tasks.py` から行う。SQLiteは配信用投影と永続受信箱で、JSON/DB直接編集やWeb/D1からの上書きはしない。
- 端末の完了変更はatomic outbox保存後に自動送信。Mac受信箱commit→revision一致時の正本更新→読戻し→applied応答→outbox解消。競合は上書きせず保持し、保存失敗は同じoperation IDで再試行する。明示applyと手動送受信は復旧用に残す。
- 未送信が確実な新操作だけは取消で取下げ可能。送信開始前に不確実性を保存し、それ以降は元ID/payloadを維持して最新希望を別保存、ack後に新IDで後続変更を送る。古いキャッシュの送信不明状態は取下げない。
- 起動・前景復帰・前景中の再試行で通信回復に対応する。バックグラウンド・終了中・Macスリープ中の常時同期は保証しない。Mac受信/正本適用とWeb・Dot会話への反映を区別する。
- 接続は既存LAN、TLS証明書ピニング、端末別認証。承認済みLaunchAgentの設定・停止手順は[常駐運用](../Integrations/DotLocalBridge/SERVICE-PROPOSAL.md)。Supabase・新規クラウド・VPN・外部公開を導入しない。

## タスクデータ作成・更新の共通手順

1. 現行CLIスキーマと[入力仕様](../Integrations/DotLocalBridge/DOT-TASK-FORMAT.md)を確認する。更新可能項目は `title/date/dateLabel/status/details/aiContext/category/subcategory/parentId/completed/project/tags/reminderAt/startTime/endTime/timeZone/deadlineDate/deadlineTime/taskKind`。id/revisionは変更JSONに入れず安定slugとexpected revisionを使う。
2. 操作直前に `pending` と `read` で最新revision・受信保留・重複・既存分類を確認する。`read` は中断した受信操作の回復とDB投影を伴うため、厳密な読取り限定では正本を変更しない隔離コピー等を使う。端末の未送信操作がある同じタスクを黙って更新しない。
3. project/tagsは正本内の実在するUUID/name参照を再利用する。サンプルUUIDを使わず、同じIDの名前不一致や重複を拒否する。新規分類は本人依頼または明示委任された整理範囲内で必要最小限だけ生成し、Gitリポジトリ対応を推測しない。parentIdはproject UUIDとは別の従来参照である。
4. 変更前の正本・受信箱の整合した復元用コピーと差分JSONを所有者専用で保持する。正式CLIのcreate/updateだけで一件ずつ保存する。省略した属性は保持する。競合・未反映操作は強制上書きしない。
5. 保存後readで対象全指定属性・件数・他タスク不変・保護する日程/期限/通知/完了/分類を照合する。Mac保存とiPhone受信・実表示・通知予約を区別し、未観測の反映を成功と報告しない。正本削除・一括置換・統合元の復活は行わない。

## 追加後の管理と抜け漏れ防止

本人からタスク追加を受けたら、dotは既存タスクとの関連/重複候補、分類、優先順位、過密を避けた仮作業日、進捗整理と見通しまで整える。通常の可逆な分類・仮配分を毎回すべて承認待ちにしない。アプリは予定確認と完了が中心。固定期限、本人が明示した予定、completed、ID/履歴を保持し、「朝ごろ」を数値時刻へ変えない。同名別IDの統合・削除を推測しない。タスク本文の購入/予約/送信等は管理委任だけで実行しない。

依頼時に取得できる会話/メッセージ参照は、`canonical_tasks.py create/update --request-ref <参照:item-key>`で既存aiContextの`[request:...]`へ保持し、再依頼前に検索する。同じ依頼の複数タスクは安定した項目キーで区別。同じ参照/同じslug/同じ作成内容の再実行は既存revisionを返し、別slugでの二重登録・内容違いは409で止める。元のaiContextは保持。取得できない参照IDを捏造しない。これは新しい受付DBや自動実行ではなく、既存欄・作業記録を使う運用である。既存58件へ出典を推測した一括追記はしない。

各依頼の終了前に、対象slug・直前/保存後revision・実際の変更項目・read-back一致・未保存/競合/判断保留を照合し、依頼の各項目を保存済みか未処理かに対応付ける。Mac保存/端末取得/通知予約/本人表示を分け、未確認を成功へ補わない。新規追加時は同一参照と内容の重複を確認し、整理後は分類未設定、期限と仮枠の混同、日別件数、意図しない重複候補を確認する。日別件数は負荷の手がかりで、所要時間未定の件数だけから過密と断定しない。

2026-10-22の読み取り点検では58件/58 slug、分類・project・tags未設定0、同名候補1組（既存の代替候補、未統合）、受信操作7件はすべてapplied、pending0。日別件数や同名候補の詳細は非公開の読取り結果に保持。依頼IDを正規化した受付列/依頼単位の未処理queue、定期自動点検はない。追加した`canonical_tasks.py audit --as-of YYYY-MM-DD`はJSON/DBを変更せず分類漏れ・日別件数・同名候補・依頼参照重複・pendingを返す。上記実データでも実行し58件/分類漏れ0/日別上限3件超なし/pending0を確認した。既存分の受付参照は未設定で、保存漏れを意味するものではないが、過去依頼への追跡は遡及できない。createはslug/取得できた依頼参照、updateはexpected revisionで保護するが、参照のない依頼・別内容の意味上の類似は手順依存。本人からの依頼そのものの取りこぼしを「完全に自動検出できる」とは説明しない。

## 表示・日程・分類の契約

- タイトルは短い体言止め、20文字程度を目安とし意味を優先する。detailsは人向けの行動・次の一歩・完了目安。aiContextは元の詳細・出典・履歴・関連・注意を保持し通常UI/Widgetへ渡さない。端末とLAN転送には含まれるため秘密領域ではない。
- dateはYYYY-MM-DD/nullの作業日・希望日。startTime/endTimeは同日のHH:mm/null。時刻指定時は実在するIANA timeZoneが必要。秒、24:00、開始なし終了、開始以前の終了、存在しないDST現地時刻を拒否する。日跨ぎ枠は未対応。「朝ごろ」から正確な時刻・所要時間を捏造しない。
- 固定期限はdeadlineDate/deadlineTimeへ分離し、本人の作業日や案件全体期限の意味を取り違えない。通知reminderAtは別のoffset付きISO秒精度で、日程整理から通知を自動新設しない。
- projectはnullまたはUUID/name、tagsはその配列。categoryはwork/private/otherを大分類表示へ使う。statusとcompletedは別で、工程・保留・検討状態から完了を推測しない。
- 日付のみは終日、時刻付きは指定zoneの開始日時を既存TaskItemへ投影。終了と固定期限は人向け詳細にも明示する。native SwiftData schemaを増やさず、Dotの名前・日程・本文整理はMac正本側、iPhone更新は完了操作のみ。
- タスクタブの初期表示は今日から7暦日の「今週」。大分類切替、プロジェクト集約、次の一歩、仮枠/希望日と固定期限の別表示。保留・検討中・統合済み・完了は週から除外する。従来の全件・日付別・タグ絞込みは残す。
- 完了/取消のUUIDを保持し、古い保存結果・古い表示ボタンで別の対象を取消さない。端末保存通知からStoreとWidget共有投影を更新する。Widget実描画の時刻はOS管理。

## 種別・状態・検索（2026-10-23）

- 種別は任意の`taskKind`。`event`=予定、`task`=具体的タスク、`idea`=やりたいこと（未具体化・順次）、`errand`=細々した用事。省略/nullは種別未設定。日付・期限・タイトルから推測分類せず、既存タスクの一括再分類はしない。更新は正規CLIでexpected revisionを使う。稼働中継がこの項目に対応してから運用する。
- 状態は種別と独立。表示はcompleted=trueを完了として優先し、未完了の「保留/保留中」「考え中/検討中」等を同じフィルターで扱う。工程statusは正本に保持し、完了/取消に伴って工程を勝手に書き換えない。未知の工程は「その他の状態」で元の文言を残す。
- タスク画面の種別・状態切替は同じStoreを参照し、選択時は表示対象を「すべて」へ戻す。仕事/私用/その他・project/tag条件は組合せ可能。行に種別と状態を表示。未設定の分類を含め全件で検索可能。
- 検索中は初期状態で「全体から検索」。今週/種別/状態/大分類/project/tag/優先度条件を跨いでタイトル・人向け詳細・project名・tag名を検索する。スイッチを切ると表示条件内の検索になる。AI補足は検索・通常表示へ出さない。Calendarの既存予定、今日の見通しはそれぞれ従来の画面に保持する。
- taskKindはDot独立JSON/転送/端末キャッシュの任意属性。TaskItem/SwiftData/バックアップschema、完了操作ID/payload/競合/確認応答は変更しない。Widgetは従来の投影を読み、種別から日程や完了を変更しない。
